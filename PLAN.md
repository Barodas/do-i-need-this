# Do I Need This? — Plan

## Decisions
- Client: Interface 16001 (build 1.60.1). Modern client, Lua 5.1, `C_*` APIs. The old quest log functions (`GetQuestLogTitle` and friends) are missing.
- Data stored as realm → faction → character, in one shared `DoINeedThisDB` for the account.
- Single WoW account only (no cross-account sync for now).
- Forever characters have surnames, and mail needs the full name. It's recorded at login from `GetUnitName("player", true)`.
- Mail between alts arrives instantly, so there's no delivery timer. Sent items count as "in mailbox" until the recipient's inbox is scanned.
- One click sends every mail needed. The game doesn't require a click per mail.
- Mails have no body text (so they disappear once emptied). The subject lists the items, or the item total when that's too long.
- Allocation: for each item, fill the highest-priority character first. The sender has no special rules and just takes its place in the priority list.
- A fallback character per realm/faction gets the excess (for storing or selling).
- Low-level characters still receive items.
- Tooltip shows who needs the item and who already has it in their own bank.
- Folder/addon name `DoINeedThis` (`?` isn't allowed in Windows file names). Display title "Do I Need This?".

## Quest data
- `Data/Quests.lua` is generated by `tools/Build-QuestData.ps1` from Wowhead (Forever) data, keeping only tradeable items. Reruns only add quests and never change existing entries.
- Quests are learned in-game from the turn-in window (`DoINeedThisDB.learned`) and used straight away. Rerunning the script bakes them into `Quests.lua`.
